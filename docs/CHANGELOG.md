# Версии

Теги git `vX.Y`. Внутри версии — что вошло и на какие грабли наступили.

## v0.7.7 — связи между клетками в режиме «Частицы»
- Проблема: в режиме «Частицы» на большом плотном мире скопления организмов
  выглядели как облако несвязанных точек — границы/форма не читались,
  отличался только цвет вида (жалоба с скриншотом: виден разрыв внутри
  явно единого скопления, а понять его форму нельзя).
- Новый чекбокс «связи между клетками» (`#bondsOn`, выкл по умолчанию —
  считается только когда включён, т.к. проход по всем живым клеткам не
  бесплатный). Между соседними по решётке живыми клетками ОДНОГО вида
  рисуется тонкая линия (`gl.LINES`, новый минимальный конвейер
  `VS_BOND`/`FS_BOND`/`progBond`/`vaoBond`) — соседство проверяется только по
  трём положительным направлениям осей (`+x`,`+y`,`+z`), чтобы не считать
  каждое ребро дважды.
- Осознанно НЕ завязано на organism `label`/`cid`: у больших миров разметка
  компонент вообще отключена (`S.hasLabels=false`, см.
  `Engine.COMPONENTS_CELL_LIMIT` в движке — ровно случай со скриншота,
  подпись HUD «организмы не считаются (большой мир)»), так что связи
  считаются по виду + соседству на решётке — это работает независимо от
  размера мира и включённости разметки компонент.
- Данные о рёбрах (`rebuildBonds()` в `rebuildInstances()`) — отдельные
  буферы (не подвыборка кубовых/частичных буферов, т.к. это пары вершин на
  ребро, а не одна вершина на клетку), но собраны и залиты в GPU той же
  схемой, что и остальные инстанс-буферы. Переключение чекбокса без новых
  данных с сервера пересчитывает связи вручную (`rebuildInstances()` из
  обработчика `#bondsOn`/из `viewer.set('bondsOn', …)`), иначе линии не
  появились бы до следующего снапшота.
- Разрыв на скриншоте — не отдельный баг рендера, а реальная топология
  симуляции (два отдельных, физически не смежных участка одного скопления);
  связи по построению не рисуют линию через клетки, которых нет — они лишь
  делают форму каждого физически смежного куска читаемой, а не сшивают
  несвязанные куски в один.
- Тест (`tests/test_web.py::test_bonds_draw_lines_between_same_species_neighbors`):
  на засеянном и прогнанном мире включение связей обязано (а) дать
  `viewer.bondCount > 0` — соседи одного вида действительно есть — и (б)
  реально увеличить закрашенную площадь по сравнению с выключенными
  связями (нарочно мелкий `ptSize`, чтобы между круглыми импосторами были
  щели, которые линии обязаны частично залить). Проверено падающим на коде
  до фикса.

## v0.7.6 — второй рендер: «Частицы» (шейдерные импосторы вместо кубов)
- Новый переключатель «Рендер: Кубы / Частицы» (кубы — по умолчанию).
  Второй шейдерный конвейер (`VS_PTS`/`FS_PTS`, программа `progPts`) рисует
  ровно те же данные, что и кубы (`B.cell`/`sp`/`lab`/`size`/`kind`/`height`
  — ни один буфер не дублируется), но через `gl.POINTS` вместо
  `gl.drawArraysInstanced` инстанс-меша куба: одна вершина на клетку вместо
  36. Второй VAO (`vaoPts`) ссылается на ТЕ ЖЕ буферы, что и кубический
  VAO, просто без per-instance divisor и без геометрии куба.
- Форма частицы — не плоский залитый кружок точки, а сферический импостор:
  нормаль восстанавливается из `gl_PointCoord` (классический трюк GPU-частиц
  из игр), поэтому у каждой частицы есть блик и объём, а не просто цветное
  пятно. Все фильтры (маска видов, мин. размер, выделенный организм,
  срез/толщина, показ камня/почвы/воды, режим окраски по виду/организму)
  продублированы из кубового шейдера один в один — что скрыто у кубов,
  скрыто и у частиц.
- Размер точки в пикселях считается в вершинном шейдере из `gl_Position.w`
  (перспектива уменьшает дальние точки, ортографика — нет, одной формулой:
  `uPointScale * uSizeMul / gl_Position.w`, а `w==1` у ортографики не
  меняется с расстоянием). Ползунок «размер частиц» (`#ptSize`) крутит
  `uSizeMul` живьём. Столбы рельефа (движки с картами высот) не могут
  вытянуться в колонну — точка не масштабируется по одной оси — вместо
  этого выше столб просто крупнее точкой (`sqrt(height)`), с явной пометкой
  в коде, что это упрощение.
- Тесты (`tests/test_web.py`): переключение рендера действительно меняет
  картинку (круглые импосторы по построению не могут закрасить всю площадь
  квадратной грани — < 79% — так что суммарная площадь живых пикселей
  обязана просесть; без этого явного bound первая версия теста проходила
  бы и с немым переключателем, ничего не делающим), состав по видам
  остаётся узнаваемым, переключение обратно на кубы возвращает прежнюю
  картинку, ползунок размера реально меняет закрашенную площадь. Оба теста
  проверены падающими на коде до фикса.
- Заодно почищена смежная хрупкость в `test_select_organism`: тест прятал
  только камень, но не почву/воду — их фиксированный цвет террейна на
  этом мире иногда попадал в тот же "ближайший по оттенку" бакет
  гистограммы, что и цвет случайного вида, эпизодически проваливая тест
  безо всякой связи с рендером частиц (поймано при вставке новых тестов
  перед этим — сдвинувшийся тайминг обнажил существовавшую проблему).

## v0.7.5 — перкуссия: озвучены дискретные события мира
- Новый опциональный слой звука — перкуссия (чекбокс «Перкуссия», выкл по
  умолчанию), поверх гармоник/голосов, никак их не заменяя. Озвучивает
  дискретные события поколения: охота (`kill`), голод/гибель животного
  (`starve`), рождение животного и растения (`birth_animal`/`birth_plant`),
  выветривание (`shock`), растворение камня (`dissolve`), и рождение/гибель
  голоса организма (churn `sf.births`/`sf.deaths`, раньше двигавший только
  огибающую голоса, отдельным ударом никогда не звучавший).
- **Принципиально без ритма/сетки/BPM** — по прямому требованию: каждый
  удар звучит ровно в момент, когда событие произошло, с небольшим случайным
  (не квантованным) разбросом внутри пачки, если событий в кадре несколько.
  Максимально хаотично, как сама жизнь клеток — не подстроено под темп.
- Бэкенд: `backend.sample_event()` дёшево описывает булев массив событием
  (сколько клеток задето + до 8 позиций для панорамы, `None` если событие не
  произошло). `step()`/`animals_step()` кладут события такта в
  `state["last_events"]`; `Engine.publish()` отдаёт их снимку РОВНО один раз
  на поколение (`pop()`, а не чтение) — иначе повторные publish() на одном
  gen (когда снимков берут чаще, чем симуляция шагает) переигрывали бы один
  и тот же удар. `WebViewer` копит события МЕЖДУ фактическими отправками
  кадра (`_merge_events`) и раздаёт накопленное строго в момент реальной
  отправки — иначе события «промежуточных» поколений (симуляция быстрее fps)
  терялись бы молча.
- Клиент: `Perc` — синтез ударных без семплов (шумовой щелчок через фильтр +
  тональное тело, свои для каждого типа события). Куча переключателей
  специально, чтобы можно было «потыкать»: общий чекбокс + громкость,
  разброс старта, ударов за событие, и на каждый тип события отдельно —
  вкл/выкл, громкость, тон.

## v0.7.4 — убрана сама периодичность, не только щелчок
- v0.7.3 размазывала СИНХРОННЫЙ момент обновления голосов, но не убирала
  саму периодичность источника: `snap.components` (размер/центр организма —
  из них берётся высота/громкость голоса) обновлялся ТОЛЬКО на тяжёлом
  пересчёте организмов (components_hz, и того реже на населённом мире).
  Между пересчётами это буквально был тот же список объектов.
  `Engine.publish()` теперь на каждом быстром такте дёшево накладывает
  старую (с последнего тяжёлого пересчёта) устойчивую id-карту на текущие
  живые клетки — обычное индексирование массива, без scipy.label. Усыхание
  и гибель уже отслеженного организма видно немедленно, каждый кадр. Рост
  за старые границы и рождение новых организмов по-прежнему видны только
  на следующем тяжёлом пересчёте — редкое дискретное событие, а не
  постоянная пульсация.
- Заодно: `describe_components()` строила Component-объект на каждый
  организм чистым питон-циклом — на фрагментированном мире сотни
  миллисекунд. Групповые агрегаты теперь считаются векторно
  (`np.add.reduceat`), Python-объекты — только для top-K: 30000
  организмов — 347мс -> <25мс.

## v0.7.3 — голоса больше не щёлкают синхронно
- **Оставшийся «метроном» после v0.7.1.** Организмы (а с ними — высота
  голоса) пересчитываются на сервере пачкой раз в components_hz — и того
  реже на населённом мире (сама разметка стоит дороже интервала; замерено
  на mergel: реально ~раз в 1.4с). Все голоса, чья высота в этот момент
  менялась, получали новую цель ровно в один и тот же миг — на слух это и
  был синхронный щелчок/аккорд на подозрительно ровном интервале, никак не
  связанный с жизнью клеток между пересчётами. `voiceJitter` теперь
  разводит старт скольжения высоты и рождения голоса по времени
  (детерминированно, по id голоса, разброс ~0-0.32с) — та же самая пачка
  теперь размазывается вместо одного щелчка.

## v0.7.2 — красочный режим звука «Кристалл»
- Новый опциональный режим звука (чекбокс «Кристалл», выключен по умолчанию,
  обычный звук не тронут):
  - Полосы (гармоники) больше не сидят на плоском целочисленном ряду
    `baseHz*h` — квантуются в ту же пентатонику, что и `base_hz`, при этом
    ступень задаёт доминирующий вид полосы. Для этого `SoundFrame` теперь
    несёт `band_species` — доминирующий вид на полосу (1..N, 0 — пусто),
    дёшево считается заодно с `bands()` (argmax по уже собранной матрице
    `counts`).
  - У каждого голоса организма — второй, детерминированно расстроенный по
    виду осциллятор (хор): разные виды звучат разным тембровым «цветом».
  - Шина реверба (синтетический экспоненциально затухающий IR) с
    пост-фейдерным посылом с шин гармоник и голосов — объём вместо сухого
    сигнала.

## v0.7.1 — рендер не стопорит разметка организмов
- **Рывки в рендере и «метроном» в звуке — одна причина.** Разметка
  организмов (scipy.label по всему кубу — нужна и таблице видов, и голосам)
  на населённом мире стоит на порядок дороже геометрии (~80мс против ~7мс).
  Считалась ПРЯМО в цикле рассылки раз в components_hz — каждый такой кадр
  стопорил рендер, а звук получал разом новый набор голосов с коротким
  «рождением» на новой высоте — то самое «нота через равный промежуток».
  Теперь разметка считается в фоновой задаче, не блокируя кадры.
- Звук: частота голоса организма раньше застывала в момент рождения — росла
  громкость, пан и вибрато, а высота нет. Теперь скользит к новой цели, если
  organism harmonic изменился у того же голоса.
- Диагностика: `snapshot_ms` в заголовке кадра раньше всегда был 0 —
  `snapshot_seconds` жил на Engine и не попадал в Snapshot.

## v0.7 — лаборатория генома
- **Отдельное окно конструктора** (кнопка «Лаборатория генома…» или клавиша G):
  слева список живущих видов с цветом, населением и поиском, справа карточка на
  каждый ген — свой значок, подпись, ползунок, поле для точного числа и
  описание. Изменённые гены подсвечены. Раньше это была узкая полоска в боковой
  панели без единого места, где видно, кто сейчас живёт.
- **Описания генов** (`GENE_DOCS` у каждого движка): не подпись в три слова, а
  что случится, если крутить — и чем этот ген важен именно в этом мире.
- **Ответвление вида** (`fork_species`): правка генома «на месте» переписывала
  вид целиком и стирала тысячу поколений отбора. Теперь можно завести потомка с
  новым id и родословной, перекрасив в него долю клеток родителя. В движках с
  фиксированными видами кнопка выключена и объясняет почему.
- Сервер отвечает автору команды результатом (`{"ok": …}`) — окно может сказать,
  какой id получился и сколько клеток перекрашено.
- Значки — свой монохромный SVG-набор в клиенте: одинаков во всех системах и
  красится темой, в отличие от эмодзи.
- Грабли: приглушение «неработающих» генов опиралось на ген `speed` и в «терре»,
  где его нет, гасило `metabolism` и `repro` у всех. Забытое открытым модальное
  окно перехватывало клики в тестах — теперь автофикстура его закрывает.

## v0.6 — кем заселять, повторный засев, выход из воды
- **Стартовый набор видов.** `start_species` в обоих движках: в «экологии» —
  номера видов (можно «только мох», «мох и травоядное»), в «терре» — архетипы
  (лишайник / бактерия / водоросль / мох) со своими местами обитания. Панель
  «Кем заселять» + кнопка «Заселить заново».
- **Повторный засев.** Вымерший мир сам не оживает: рождение требует живых
  соседей. Галочка `reseed` подсевает стартовые виды — по умолчанию **только при
  полном вымирании** и не чаще `reseed_every` поколений; живому миру подсев не
  приходит, чтобы не стирать отбор. Общий крючок `Rules.seed()`, вызывается из
  `Engine.advance()`.
- **Растения выходят из воды** («терра»): тень воды считается для любой клетки
  под уровнем водоёма, а не только для донной, стебель под водой кормится геном
  `water`. Уровень моря по умолчанию 0.18 → 0.12 — воды было слишком много.
- **Фильтр рельефа**: в клиенте отдельные галочки камень / почва / вода.
- Документация: разбор всех восьми видов «экологии» (кто это на самом деле и
  почему в прогоне столько травоядных и «корки») — `docs/engines/ecology.md`.

## v0.5 — «терра», быстрый рендер, звук из населения
- **Рендер перестал идти рывками.** История поколений была безграничной (на
  2 млн поколений — сотни мегабайт и копия под замком на каждый кадр); теперь
  ограниченная очередь + прореженная длинная. Заголовок кадра (история 400×64,
  рельеф n², имена 64 видов) сериализовался в JSON каждый кадр прямо в цикле
  сервера — 50 мс; теперь всё это шлётся только при изменении и кодируется в
  отдельном потоке. Метки организмов не шлются, когда их не считают.
  Кадр: 50 мс → 2.4 мс.
- **Подложка рисуется столбами** (один инстанс на столбец, растянутый по
  высоте) и передаётся картами высот, а не поклеточно. Камень выглядит
  массивом, а не тонкой коркой — это же чинит «висящую в воздухе» подложку в
  движке «экология». Вода рисуется полупрозрачным проходом.
- **Новый движок «терра»**: камень на треть куба, многооктавный рельеф без
  единственного холма, вода и почва с самого начала, реки и наносы,
  неравноценная эрозия (1 камень → 3 почвы), ниша из трёх генов, бактерии
  удобряют почву, растения-симбионты садятся только на удобренную, цвет вида
  вычисляется из генома.
- **Звук**: основной тон больше не фиксирован — его задаёт население
  (пентатоника по доминирующему виду, октава по плотности жизни), голоса
  строятся из видов, если организмы не размечены (на больших мирах звук был
  ровным фоном именно поэтому). В клиенте — галочка «тон из населения».
